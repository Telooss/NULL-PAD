# OBS + MIDI — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** une touche ou une molette du NULL/PAD pilote OBS (scène, mute d'une source, stream, enregistrement, replay) et envoie des notes / CC MIDI à Ableton par un port MIDI virtuel.

**Architecture:** deux modules du moteur existant.
- `engine/src/obs.rs` : un client **obs-websocket v5** maison, synchrone (crate `tungstenite`, sans TLS). Un thread OBS possède la connexion. Les actions lui arrivent par un canal : l'appui ne fait qu'un `send`, jamais d'attente réseau. Connexion paresseuse au premier envoi, reconnexion à l'envoi suivant après une coupure.
- `engine/src/midi.rs` : sortie MIDI par `midir` (WinMM). Le port est un port **existant**, trouvé par sous-chaîne de son nom. On ne crée pas de pilote : l'utilisateur crée un port virtuel avec loopMIDI (gratuit) ou une boucle Windows MIDI Services. Les deux sont visibles en WinMM.
- Branchement dans `SystemExecutor`, rechargement à chaud par le `on_reload` existant.

**Tech Stack:** Rust stable, crates du moteur + `tungstenite = { version = "0.30", default-features = false, features = ["handshake"] }`, `sha2 = "0.11"`, `base64 = "0.23"`, `midir = "0.11"` (versions vérifiées sur crates.io le 2026-11-07). `serde_json` est déjà là.

**Spec:** `docs/superpowers/specs/2026-11-05-logiciel-macropad-design.md` §5 :
- « OBS via obs-websocket v5 : changer de scène, couper/rétablir une source, démarrer/arrêter stream ou enregistrement, sauvegarder le replay » ;
- « MIDI (note, CC) vers un port MIDI virtuel, pour Ableton. Le moyen de créer le port … est au choix du builder ».

## Choix (rulings du contrôleur)

- **Client OBS maison plutôt que `obws`.** `obws` impose tokio, alors que le moteur est en threads synchrones. Le protocole nécessaire est petit : Hello, Identify, Request, RequestResponse, plus l'authentification SHA-256. On le teste contre un faux serveur local.
- **Port MIDI existant plutôt qu'un port créé par l'appli.** Créer un port virtuel sous Windows demande un pilote (teVirtualMIDI) ou l'API Windows MIDI Services. C'est trop lourd pour la v1. Le README explique loopMIDI.
- **`MidiNote` = tap** : note on puis note off juste après, sur l'appui. Le moteur n'a pas d'action au relâchement. Pour une note tenue, ce sera plus tard.
- **Molette vers Ableton** : `MidiCc` avec `value: 1` (horaire) et `value: 127` (anti-horaire). Dans Ableton, mapper en mode « Relative (2's Comp.) ». C'est documenté.

## Protocole obs-websocket v5 (à vérifier dans `obsproject/obs-websocket`, `docs/generated/protocol.md`)

1. Le serveur envoie **Hello** `{"op":0,"d":{"rpcVersion":1,"authentication":{"challenge","salt"}?}}`.
2. Le client répond **Identify** `{"op":1,"d":{"rpcVersion":1,"authentication":<str>?,"eventSubscriptions":0}}`.
   - `secret = base64(sha256(password + salt))`
   - `auth = base64(sha256(secret + challenge))`
3. Le serveur confirme par **Identified** `{"op":2}`.
4. Les requêtes partent en **Request** `{"op":6,"d":{"requestType","requestId","requestData"}}`.
5. Les réponses arrivent en **RequestResponse** `{"op":7,"d":{"requestId","requestStatus":{"result":bool,"code","comment"?}}}`.
6. Correspondance action → requête :
   - `ObsScene` → `SetCurrentProgramScene{sceneName}` ;
   - `ObsMute` → `ToggleInputMute{inputName}` ;
   - `ObsStream` → `StartStream` / `StopStream` / `ToggleStream` ;
   - `ObsRecord` → `StartRecord` / `StopRecord` / `ToggleRecord` ;
   - `ObsReplaySave` → `SaveReplayBuffer`.

## Modèle de config (source de vérité)

```json
"obs":  { "host": "127.0.0.1", "port": 4455, "password": null },
"midi": { "port": "NULL-PAD" }
```

Actions :
- `{ "type": "ObsScene", "scene": "Jeu" }`
- `{ "type": "ObsMute", "input": "Micro" }`
- `{ "type": "ObsStream", "op": "Toggle" }` (`op` : `Start` | `Stop` | `Toggle`)
- `{ "type": "ObsRecord", "op": "Toggle" }`
- `{ "type": "ObsReplaySave" }`
- `{ "type": "MidiNote", "channel": 1, "note": 60, "velocity": 100 }`
- `{ "type": "MidiCc", "channel": 1, "cc": 20, "value": 1 }`

## Global Constraints

- Sections `obs` et `midi` en `#[serde(default)]` : les configs existantes restent valides, `version` reste 1.
- Bornes :
  - `channel` 1..=16 ;
  - `note` et `cc` 0..=127 ;
  - `velocity` 1..=127 ;
  - `value` 0..=127 ;
  - `scene` et `input` non vides ;
  - `port` (OBS) 1..=65535.
- L'appui ne bloque jamais : aucune entrée/sortie réseau ni attente sur le thread du worker. Les envois MIDI passent par WinMM (`send` ≪ 1 ms) : ils restent sur le worker.
- OBS absent, mauvais mot de passe, scène inconnue, port MIDI introuvable → un `warn!` clair, et le moteur continue. Pas de spam : au plus un essai de connexion OBS par action.
- Connexion OBS avec un délai maximal de 2 s. Mot de passe jamais écrit dans les logs.
- Aucun test automatique ne contacte un vrai OBS ni n'ouvre un vrai port MIDI. Les tests OBS utilisent un faux serveur `tungstenite` sur `127.0.0.1:0`. Ceux qui touchent un vrai port sont `#[ignore]`.
- Commandes cargo sans `rtk`. Commits terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Branche `feat/obs-midi`.

## Review Focus

1. **OBS fermé puis rouvert** : la première action après le retour d'OBS se reconnecte, et aucune action ne bloque l'appui. Test : Task 2.
2. **Mauvais mot de passe / OBS sans mot de passe alors que la config en a un (et l'inverse)** : un `warn!` explicite, sans plantage. Test : Task 2.
3. **Spam d'une touche OBS pendant qu'OBS est fermé** : la file ne grossit pas sans fin, et un essai de connexion échoué ne bloque pas les suivants plus de 2 s. Test : Task 2.
4. **Port MIDI absent (loopMIDI fermé)** : un `warn!`, puis un nouvel essai au prochain envoi. Test : Task 3.
5. **Valeurs MIDI hors bornes dans le JSON** : la config est refusée et la dernière valide est gardée. Test : Task 1.

### Task 2: Client obs-websocket v5

**Files:** Create `engine/src/obs.rs` (+ `pub mod obs;` dans `lib.rs`). Modify `engine/Cargo.toml` (`tungstenite`, `sha2`, `base64`). Test : module `tests` de `obs.rs`.

**Interfaces — Produces :**
- `pub fn auth_string(password: &str, salt: &str, challenge: &str) -> String`
- `pub fn request_for(action: &Action, id: u64) -> Option<serde_json::Value>` : le message op 6, ou `None` si l'action n'est pas OBS.
- `pub struct ObsHandle { tx: Sender<ObsCmd> }`, qui dérive `Clone` :
  - `pub fn send(&self, action: Action)`
  - `pub fn apply(&self, s: &ObsSettings)`
- `pub fn start_obs() -> ObsHandle` : lance le thread OBS. Il garde au plus une connexion.
  - **Envoi** : s'il n'est pas connecté, il se connecte (TCP `connect_timeout` 2 s, puis handshake WS, Hello, Identify, attente d'Identified, avec un `read_timeout` de 2 s pendant le handshake). Ensuite il envoie la requête et lit la réponse (`read_timeout` 2 s). Si `result == false` → `warn!` avec `code` et `comment`. Une erreur d'entrée/sortie ferme la connexion : l'envoi suivant se reconnecte.
  - **`apply`** : il ferme la connexion si `host`, `port` ou `password` ont changé.
  - **File** : `sync_channel(32)` avec `try_send`. Quand elle est pleine → `warn!` et l'action est jetée (Review Focus 3).

### Task 3: Sortie MIDI

**Files:** Create `engine/src/midi.rs` (+ `pub mod midi;`). Modify `engine/Cargo.toml` (`midir`). Test : module `tests` de `midi.rs`.

**Interfaces — Produces :**
- `pub fn note_on(channel: u8, note: u8, velocity: u8) -> [u8; 3]` : `0x90 | (channel-1)`.
- `pub fn note_off(channel: u8, note: u8) -> [u8; 3]` : `0x80 | (channel-1)`, vélocité 0.
- `pub fn cc(channel: u8, cc: u8, value: u8) -> [u8; 3]` : `0xB0 | (channel-1)`.
- `pub fn pick_port(names: &[String], wanted: &str) -> Option<usize>` : sous-chaîne, sans tenir compte de la casse. La première correspondance gagne.
- `pub struct Midi { conn: Mutex<Option<midir::MidiOutputConnection>>, port: ArcSwap<String> }` :
  - `pub fn new() -> Arc<Midi>`
  - `pub fn apply(&self, s: &MidiSettings)` : ferme la connexion si le nom a changé.
  - `pub fn send(&self, msgs: &[[u8; 3]]) -> Result<(), String>` : ouvre la connexion si besoin (liste des ports, `pick_port`, `connect`). Sans port → `Err("port MIDI \"…\" introuvable (loopMIDI lancé ?)")`. Une erreur d'envoi ferme la connexion, et le prochain appel rouvre.
